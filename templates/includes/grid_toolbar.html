{% load ui %}{% comment %} The one list toolbar (docs/ui-standards.md section 5, rule 1), inside the list's section.card.vr-table-card above the table: search, up to three everyday filters, More filters (a Bootstrap collapse), Apply, Clear all when anything is active, Columns at the right, then the active filters as removable chips. A GET form: the server filters, sorts and paginates; changing a filter returns to page 1. Built from includes/grid_search.html, grid_columns_button.html and filter_chips.html. Parameters: label accessible name of the form, e.g. "Filter samples" (required) q current search text; placeholder, search_id (default "grid-q") tune the search box no_search truthy for a list without free-text search inline up to three bound fields shown in the row (e.g. a list built in the view) more bound fields behind More filters; omit when there are none more_open truthy when one of the "more" filters is active; the panel also opens when invalid invalid the filter form's errors (filter_form.errors); opens More filters chips the active filters as [{label, value, remove_url}] (active_filters); shown as removable chips under the toolbar active truthy when any filter or search is active (a default value is not); shows Clear all. chips or q also count clear_url target of Clear all; default request.path grid the table's data-vr-grid key: renders the Columns button; omit for entry grids sort the current sort value, carried when hidden is not given hidden bound hidden fields to carry; without it sort and rows per page (request.GET.per_page) are carried Documented page reads ({% grid_toolbar %}, core/templatetags/ui.py): q, placeholder, inline, more, more_open, active and sort when not passed, and filter_form and active_filters (for invalid and chips when those are not passed); the list views put them in the context. The form posts to request.path.
